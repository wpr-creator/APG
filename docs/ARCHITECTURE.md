# APG site architecture

APG is a dependency-free static site published from the repository's `main`
branch with GitHub Pages. There is no build step: the files in the repository
are the files students receive.

## Canonical student experience

The current home experience is the hash-routed application rooted at
`index.html`:

- `index.html` defines the application shell and accessible page structure.
- `app.js` handles routing, rendering, interactive activities, and the teacher
  editor.
- `styles.css` contains the current shell's visual and responsive system.
- `course-data.js`, `glossary-data.js`, and the other `*-data.js` files provide
  curriculum and activity data.
- `site-content.json` contains frequently changed course state such as the
  current unit, unlocks, agenda, upcoming work, and assignment URLs.
- `us-politics-events.json` is the source-linked political-history calendar.

When changing the current home, agenda, units, foundations, glossary, or skill
builder experience, start with these files.

## Standalone curriculum pages

The root `unit*.html`, document, assignment, and tool pages remain supported
student routes. Their shared navigation is generated by `nav-render.js`, and
their shared presentation is primarily supplied by `styles-gov-theme.css`.

The full Supreme Court case pages live under `cases/`. Same-named case files at
the repository root are compatibility redirects retained for old bookmarks.
Do not add independent content to the root redirect files.

## Legacy application files

Files including `index-app.js`, `data-core.js`, `data-content.js`,
`data-extra.js`, `data-skills.js`, `styles-base.css`, `styles-pages.css`, and
`styles-skills.css` support preserved standalone pages and earlier tools. They
are not the implementation of the current `index.html` shell. Confirm which
HTML page loads a legacy file before modifying or removing it.

These files were reference-audited on August 3, 2026. The JavaScript data files
remain loaded by `ap-tools.html`, and the legacy stylesheets remain shared by
the unit, document, case, agenda, extension, and presidential-library pages.
They therefore cannot be removed without first migrating those supported
routes. A future retirement should migrate one page family at a time, update
its references, run validation, and verify the published legacy URLs before
deleting shared files.

Likewise, `content.json` supports older standalone experiences;
`site-content.json` is the current shell's editable course-state file.

## Teacher publishing

Typing `dev` outside a form field opens the teacher editor. Preview data and
the GitHub token are stored only in that browser. Use a fine-grained personal
access token restricted to the `wpr-creator/APG` repository with only
**Contents: Read and write** permission. Remove the token from the editor when
using a shared device.

The editor writes only `site-content.json` on `main`. Structural or code
changes should still be made on a branch and reviewed in a pull request.

## Validation

Run `node scripts/validate-site.js` before publishing code changes. GitHub
Actions runs the same validator for every pull request and every push to
`main`. The validator checks JavaScript and JSON syntax, local references,
required shell content, compatibility redirects, calendar integrity, basic
HTML accessibility, duplicate IDs, macOS metadata, and large-image budgets.
